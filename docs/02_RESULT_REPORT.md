# 제주 EV Plan B AI Agent — 결과 설명자료

## 1. 문제·목표

제주 전기차 이용자가 목적지 주변 충전소 한 곳만 선택하면 점유·고장·이용 제한 시 다시 대안을 찾아야 합니다. 본 서비스는 목적지·배터리 조건을 바탕으로 Plan A와 이용 불가 시 확인할 Plan B를 함께 제시합니다. 정확한 대기분 예측·충전 성공 보장이 아닌 충전 의사결정 지원이 목표입니다. 사용자층은 제주 전기차 여행자와 도민입니다.

## 2. 구조

브라우저(static/app.js) → FastAPI(server.py) → LangGraph(ConversationGraph) → AgentService → 검색·추천·외부 도구 → JSON 결과 → 지도·카드.

LangGraph는 START → plan → END의 단일 실행 노드와 InMemorySaver입니다. 다중 에이전트나 복잡한 자율 계획 그래프가 아닙니다. plan이 이전 목적지·배터리·추천·제외 시설을 이어받아 서비스를 호출합니다. Gemini는 입력 구조화·설명 보조이며 시설 순위·가용성·배터리 계산을 독자적으로 결정하지 않습니다. RAG·벡터 DB·파인튜닝은 없습니다.

## 3. 주요 기능

| 기능 | 구현 | 제한 |
|---|---|---|
| 목적지 검색 | 규칙/Gemini·내장 목록·카카오 | 모호하면 보충 질문, 키 없으면 자유 장소 제한 |
| Plan A/B | 운영·공급·대체관계·실시간·허브 보조 지표 | 전 제주 모든 충전시설·도로 전수 최적화 아님 |
| 배터리 | 대표 전비·용량·출발지 | 직선거리 기반 참고 |
| 자동차 이동 | 카카오 도로거리·시간·폴리라인 | 실패 시 미확인, 시간 조작 없음 |
| 과거 이력 | 허브 4종·동봉 281곳 | 현재값과 구분 |
| 멀티턴 | 조건 유지·A/B 제외·재추천 | 서버 재시작 시 소실 |
| 상태 변경 | 열린 브라우저에서 A/B 점검·전환 안내 | 자동 내비 전환 아님 |
| 사용자 화면 | v8 지도+패널, 차/기준 분리 | 허브는 짧은 요약과 접힌 상세 |

## 4. 판단·종료 조건

후보의 도달 가능 추정과 현재 가용성 그룹을 먼저 비교한 뒤 선택 기준으로 정렬합니다. 이동시간 우선은 인접 최대 5곳 경로를 비교합니다. 도달 가능 후보가 부족하면 경고 후보가 나올 수 있으므로 완전한 안전 필터라고 표현하지 않습니다. 추천 또는 보충 질문 반환으로 종료합니다. 사용자가 장소·이동을 최종 결정하며 예약·과금·차량 제어는 없습니다.

허브는 station_context()의 카드 근거·최대 7점 보정·대기 위험 우선 정렬에 반영합니다. 조회 건수만으로 성능 향상을 주장하지 않습니다. 유동인구만으로 시설 혼잡을 단정하지 않습니다.

## 5. 결과·검증

900곳 카탈로그를 사용한 로컬 API, 기본 추천, 멀티턴, 보충 질문, 오류 대응, 파싱·페이지 반복·UI 요약 테스트를 수행했습니다. 사용자 제공 JSON을 제출판에 동봉하여 키 없이 weekly 346곳/wait 16곳/daily 340곳/floating 43읍면동이 로드되고 추천 근거로 사용됨을 검증했습니다. 실제 API 재수집·최신 충전기 상태 검증과는 다릅니다. 결과는 docs/03_VALIDATION.md와 validation_results.json을 참조합니다.

충전 성공률·실제 대기시간 감소·평균 주행시간 감소·운영비 절감은 아직 실증하지 않았습니다. 향후 같은 출발지·목적지·조회 시점에서 거리 우선과 Agent 결과를 비교하고, 현재 사용 가능 추천률·대안 확보율·도로시간·결측률·사용자 완료율을 측정해야 합니다.

## 6. 한계

과거 자료의 시차, 900곳과 외부 자료의 범위 차이, 명칭·ID 연결 누락이 있습니다. 시간 단위·자료 이용조건·기존 분석표 출처 일부는 팀 확인이 남았습니다. LLM은 제공 사실만 사용하도록 요청하지만 완전한 자동 사실검증기는 없습니다. 수치 카드는 구조화 결과로 렌더링합니다.

공개 운영용 인증·사용자별 호출 제한·영속 세션 저장은 없습니다. 배포에는 비용 한도·접근 제한·사용량 감시가 필요합니다. 브라우저·API 통신이 중단되면 최신 상태를 보장하지 못합니다.

## 7. 센터 활용

센터 PC에 Python을 설치하고 브라우저에서 이용하는 데모로 제공합니다. 데이터 출처·기간·이용조건과 API 연결 상태를 담당자가 확인하도록 합니다. 정식 서비스 전 최신 자료 갱신, 시설 ID 감사, 사용자 평가, 접근 제어, 배터리 모델 보완이 필요합니다. 로컬 GPU 모델은 사용하지 않으나 센터 실제 PC 구동은 별도 확인해야 합니다.

## 8. 기존 작업과의 관계

기존 충전망 분석 자료를 바탕으로 이번 서비스에 자연어 입력·조건 기억·실시간/도로 API·Plan A/B 사용자 흐름을 구현했습니다. 이전 공모전/연구 사용 이력과 이번 신규 개발의 정확한 범위는 팀이 보완해야 합니다.
